# Every key lives under one hash tag

Every key is `{<prefix>}:…`, every script declares in `KEYS` the fixed structures it touches (`pending`, `due`, `locks`, `tasks`, …) so it routes to the slot, and the shared library ([`lua-library.ts`](../../src/engine/lua-library.ts)) derives the id-scoped keys, a run's record and side keys, its indexes, a key's waiting list and slot set, from the hash-tagged prefix, the same shapes [`engine-keys.ts`](../../src/engine/engine-keys.ts) builds, so the layout already fits Redis Cluster at one slot: Cluster needs every key under the one tag and one declared key to route on, and a script that discovers the ids it touches, as `fetch` or `promote` does, could not declare their keys without a second round trip. 0.2.0 ships no Cluster client because nothing needed it yet; adding one later is additive, while dropping the braces or deriving a key outside the hash-tagged prefix would break that silently, since CI runs a single node. Neither is dead weight. Decided in [Failover, Cluster and supported servers](https://github.com/flolefebvre/nextasking/issues/133).
